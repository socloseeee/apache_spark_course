cache и persist: выбираем уровень хранения

В этом уроке речь о DataFrame в PySpark 3.5.3. cache() использует уровень MEMORY_AND_DISK_DESER. Такой же уровень выбирает persist() без аргумента.

from pyspark import StorageLevel

df.cache()
# Эквивалентный вариант для DataFrame без назначенного уровня:
# df.persist(StorageLevel.MEMORY_AND_DISK_DESER)

persist(level) позволяет выбрать другой способ хранения. Он тоже ленивый: блоки появляются при выполнении действий, которые вычисляют эти данные.

Основные уровни

УровеньКак хранит блокиЧто учитывать
MEMORY_AND_DISK_DESERВ памяти; не поместившиеся блоки — на дискеУровень по умолчанию для DataFrame; польза зависит от повторного использования
MEMORY_ONLYТолько в памятиНе сохранённые или вытесненные блоки придётся вычислять заново при обращении к ним
DISK_ONLYНа локальных дисках executorsЧтение с диска может быть выгоднее повторного дорогого вычисления; это нужно измерять

MEMORY_AND_DISK тоже существует, но это другой уровень, не точное имя значения по умолчанию у DataFrame. Название MEMORY_ONLY_SER из примеров Scala нельзя переносить в PySpark 3.5.3: такой константы в его стандартном Python API нет.

Как сменить уровень

Повторный вызов persist с другим уровнем не переключает уже сохранённый DataFrame. Сначала освободите прежний кэш:

df.unpersist(blocking=True)
df.persist(StorageLevel.DISK_ONLY)
print(df.storageLevel)  # проверить выбранный уровень в настоящем Spark

Уровни с суффиксом _2 запрашивают две копии блоков. Размещение реплик требует доступных executors и ресурсов; в локальной практике это не отдельная система резервного копирования.

Для собеседования: назовите API и версию, объясните повторное использование результата и компромисс памяти, диска и пересчёта. Универсального «самого быстрого» уровня нет.

Справка: DataFrame.persist в ветке 3.5, StorageLevel.
