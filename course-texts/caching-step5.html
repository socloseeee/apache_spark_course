unpersist и типичные ошибки кэширования

Освобождаем сохранённые блоки

Когда повторное использование результата завершено, вызовите unpersist(). Он снимает пометку и освобождает блоки этого кэша из памяти и с диска. Сам DataFrame остаётся доступен: при следующем действии необходимые данные могут быть вычислены заново.

df.cache()
# ... действия, которые используют df несколько раз ...
df.unpersist()

По умолчанию blocking=False: вызов не ждёт удаления всех блоков. Если для следующего этапа важно дождаться освобождения, используйте df.unpersist(blocking=True).

Завершение одного job само по себе не означает очистку кэша: он предназначен для повторного использования между действиями. При нехватке памяти блоки могут вытесняться; держать ненужные результаты до конца приложения не стоит.

Типичные ошибки

ОшибкаПочему это мешает
Кэшировать результат для одного использованияДобавляются расходы на сохранение, которые обычно не успевают окупиться
Сохранять слишком много или слишком широкие данныеВозникает конкуренция за память, вытеснение блоков и дополнительные чтения или пересчёты
Забывать unpersistНенужный кэш может занимать ресурсы и после завершения отдельного job
Считать is_cached=True доказательством заполненияФлаг показывает пометку; фактические блоки появляются при вычислении
Выбирать место кэша без учёта следующих запросовСохраняются лишние строки или остаются дорогие повторные преобразования

Где поставить cache

Ищите общий результат, который действительно используют несколько последующих действий. Обычно полезно сначала применить общие фильтры и оставить нужные колонки. Если ветвям нужны разные исходные данные, место кэша выбирают с учётом всех ветвей — правило «сырьё кэшировать всегда плохо» неверно.

Пример для df_raw с полями status, client_id и amount:

from pyspark.sql import functions as F

df_clean = (df_raw.filter("status = 'completed'")
            .select("client_id", "amount").cache())
try:
    print(df_clean.count())
    df_clean.agg(F.sum("amount")).show()
finally:
    df_clean.unpersist()

Это пример размещения и освобождения кэша, а не обещание ускорения. На настоящем Spark сравните весь набор действий с кэшем и без него: учитывайте первое заполнение, повторные чтения и расход ресурсов. В Spark UI проверьте сохранённые блоки, в плане — использование кэша.

Справка: DataFrame.unpersist.
