# Замечания к методике сквозной проверки, 17.09

Первый и повторный полные прогоны notebooks 00–05 завершились успешно.
Между контрольными снимками bronze вырос с 205890 до 617670 строк: в журнале
Kafka виден объём трёх исходных публикаций, а не двух. Точное происхождение
дополнительной публикации в прерванной и возобновлённой работе проверяющих
процессов не установлено. Не следует представлять этот опыт как строго две
публикации producer. Сырые сообщения сохранены; дубликатов Kafka offsets нет.

Первый скрипт сравнения ошибочно требовал `after_count == 2 * before_count`
и остановился только на этом условии. Остальные 18 проверок совпадения данных
и итогов уже прошли. Критерий исправлен по назначению bronze: при повторной
доставке он сохраняет новые offsets, а silver и витрины сохраняют бизнес-результат.
Теперь отдельно проверяются рост raw-журнала, отсутствие дублей offsets,
полнота диапазонов, содержимое всех строк silver/SCD2 и витрин, точные суммы
и количество покупок. После пересоздания Kafka без новой генерации bronze
должен остаться полностью неизменным — этот критерий строгий.

Опыт подтверждает устойчивость результата к повторной доставке, но не
измеряет пропускную способность и не моделирует конкурирующих writers.
Статус Metabase UI и дифференциального прогона тренажёра указывается отдельно.
