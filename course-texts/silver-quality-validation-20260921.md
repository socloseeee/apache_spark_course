# Проверка неденежных правил Silver — 21.09.2026

В локальном `02_silver.ipynb` исправлен риск подмены ключа при приведении типа.
На Spark 3.5.3 строка `"101.5"` превращалась в `101` и проходила проверку
положительности. Дробный `client_id` мог поэтому связать счёт с другим клиентом.
Также `tx_id` из пробелов, табуляции или перевода строки проходил проверку длины.
Поведение воспроизведено как отдельным SQL-примером, так и выражениями ноутбука.

Теперь CSV-идентификаторы проверяются до `cast`: цифры, допускаются обычные
пробелы по краям; результат должен помещаться в LongType и быть положительным.
Дробная запись, экспонента и знак `+` не входят в объявленный формат источника.
Отказ от `+106` и `102.0` — уточнение формата; его не следует представлять как
отдельную потерю точности. Принятые ID с ведущими нулями нормализуются как числа.
Диагностика отклонённых записей сохраняет `client_id_raw` / `account_id_raw`;
эти колонки удаляются перед дедупликацией принятых строк. `tx_id` проверяется
на наличие непробельного символа средствами регулярного выражения Spark.

## Границы доказательства

Выполняются реальные выражения ячеек 4, 6, 8 и `save_clean` из notebook 02.
Входы — явные небольшие фикстуры, построенные через JVM-выражения над `spark.range`;
отдельные Python workers не нужны. Из `save_clean` исключены запись и отображение,
остальные вычисления и проверки сохранены. Денежный адаптер меняет только границу
создания тестовых DataFrame. Хеши ноутбука, проверок и адаптера включены в JSON.
Временная метка перед сравнением форматируется в UTC внутри Spark, чтобы локальный
часовой пояс Python при `collect()` не исказил тест.

Это не проверка CSV-парсера, всех вариантов JSON, всех Unicode-символов, скорости,
одновременных writers или записи в S3/Delta. Маркер `_case` в фикстурах клиентов
и счетов служит только для сопоставления отклонённых строк с исходными примерами.
95 входов не являются доказательством корректности при любом возможном вводе.

Полный контейнерный notebook 02 и 20/20 сравнений от 20.09 относятся к редакции
**до сегодняшнего изменения ключей**. Позднее 21.09 Docker стал доступен, и текущий
notebook 02 полностью выполнен с MinIO/Delta. Независимое чтение 26.09 подтвердило
20/20 сравнений данных и 23/23
проверки хранения. [Отдельный отчёт](silver-storage-validation-20260921.md).
Контрпримеры выше остаются проверкой выражений без записи; новый полный запуск
использует основной учебный набор. Полные прогоны notebooks 00–05 по-прежнему
