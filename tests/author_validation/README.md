# Дополнительные проверки для автора

Это отдельный опыт на изолированной учебной среде с настоящими MinIO и
ClickHouse. Он не входит в обязательный маршрут ученика и не запускается
автоматически командой `pytest`.

`run_publication_failure.py` извлекает функции `ch`, `literal`, `mart_totals`
и `load_mart` из указанного notebook 05 без изменения их кода. Настройки
подключения берутся из тех же переменных окружения, что использует notebook.
Нужны установленные зависимости `boto3` и `requests`.

Запускайте только в проверочной копии стека после успешного notebook 05:

```bash
python tests/author_validation/run_publication_failure.py notebooks/05_clickhouse.ipynb validation-results/publication-failure
```

Из корня Jupyter, где notebooks открываются непосредственно в рабочей папке,
путь к notebook — `05_clickhouse.ipynb`.

Опыт создаёт новую Atomic database и новый бакет с уникальными именами:

1. Старая тестовая витрина содержит строку `old` на 7.77 RUB.
2. Отсутствующий источник вызывает реальную ошибку чтения ClickHouse.
   Проверяется доступность и неизменность старой таблицы.
3. Для существующего Parquet намеренно задан отсутствующий ключ сортировки.
   Чтение контрольных итогов проходит, создание staging завершается ошибкой,
   EXCHANGE не выполняется, старая таблица сохраняется.
4. С правильным ключом публикация проходит: две строки на 35.25 RUB заменяют
   старую витрину, прежняя строка доступна под staging-именем.
5. Сверяются хеши всех строк трёх существующих витрин и список объектов gold.
   Тестовая база и бакет удаляются; существующие gold не изменяются.

Результат записывается в `result.json`. Успех требует всех проверок и удаления
созданных тестовых объектов. Пароли, SQL с ключами и тела серверных ошибок
в отчёт не записываются.

Проверка **18.09.2026: 11/11**, ClickHouse 25.3.2.39; исходный notebook и AST
функций зафиксированы хешами в
[результате](../../course-texts/e2e-validation/publication-failure-20260918.json).

Это проверка двух конкретных ошибок до переключения и последующей успешной
публикации. Она не моделирует остановку сервера во время записи, тайм-аут после
EXCHANGE, конкурирующих writers или общую транзакцию для нескольких витрин.

## Денежный формат Silver

`run_silver_money.py` проверяет фактические выражения и правила notebook 02 на
настоящем Spark 3.5.3. Нужны PySpark и Java; `course_checks.py` должен находиться
рядом с указанным ноутбуком. Источники заменены небольшими фикстурами, запись
Delta/S3 не выполняется. Проверка не входит в обязательные упражнения ученика.

```bash
python tests/author_validation/run_silver_money.py notebooks/02_silver.ipynb validation-results/money.json
```

Успешный результат требует `passed: true`, отсутствия ошибок выполнения и всех
успешных проверок. Режим `--observe` нужен только для наблюдения старой редакции:
код завершения 0 в нём не означает соответствие новому денежному контракту.

20.09.2026: 70 денежных входов, 214/214 проверок. Дополнительно выполнен полный
notebook 02 на учебном стеке и пройдены 20/20 сравнений данных до и после.
[Методика и ограничения](../../course-texts/money-validation-20260920.md).

## Идентификаторы и другие правила качества

```bash
python tests/author_validation/run_silver_quality.py notebooks/02_silver.ipynb validation-results/quality.json
python tests/author_validation/run_silver_money_jvm_fixtures.py notebooks/02_silver.ipynb validation-results/money-jvm.json
```

Оба варианта используют настоящий Spark 3.5.3. Первый проверяет неденежные
правила ноутбука; второй повторяет существующие денежные проверки. Фикстуры
построены JVM-выражениями над spark.range, поэтому отдельные Python workers
не требуются. Запись в Delta/S3 исключена. Оба runner должны находиться рядом
с run_silver_money.py; course_checks.py — рядом с проверяемым ноутбуком.
Режим --observe у quality runner предназначен только для сравнения старой
редакции: код завершения 0 при несовпадениях не означает успешную приёмку.
Результат 21.09: 95 входов/278 проверок и денежная регрессия 214/214.
[Точные условия](../../course-texts/silver-quality-validation-20260921.md).
